# Contributing to Awesome Compliance Automation

Thank you for your interest in contributing! This list is maintained by [TrazTech](https://traztech.ca) and aims to be the most comprehensive compliance automation resource on GitHub.

## Guidelines

### Adding a Tool or Resource

Please ensure your submission meets the following criteria:

1. **Relevant**: The tool or resource must be directly related to compliance automation, GRC, security, or privacy.
2. **Active**: The project should be actively maintained. For open-source projects, check that there have been commits within the last 12 months.
3. **Quality**: The tool should be production-ready or have significant community adoption. Beta/alpha tools are acceptable if they fill a unique niche.
4. **Not a duplicate**: Search the list first to make sure the tool is not already included.

### Format

Please follow the existing format:

**For tools in a list:**
```
- [Tool Name](https://example.com): Brief description of what the tool does and its key differentiator.
```

**For tools in a table:**
Follow the existing column structure for that section.

### Rules

- One tool per pull request (makes review easier).
- Add the tool to the appropriate section. If it fits multiple sections, add it to the most relevant one and mention framework coverage in the description.
- Keep descriptions concise (one to two sentences).
- Use ` - ` (space hyphen space) between the tool name/link and the description.
- Do not include referral links or affiliate codes.
- Do not include tools that are primarily marketing pages without a real product.
- Open-source tools should include a link to the GitHub/GitLab repository.

### Suggesting a New Section

If you believe a new section is needed, open an issue first to discuss it before submitting a PR.

### Reporting Issues

- **Dead links**: Open an issue or PR to remove/update the link.
- **Inaccurate descriptions**: Open a PR with the corrected description and a source.
- **Discontinued tools**: Open an issue so we can review and remove.

## Pull Request Process

1. Fork the repository.
2. Create a new branch (`git checkout -b add-tool-name`).
3. Make your changes following the format guidelines above.
4. Ensure the list is still alphabetically ordered within its section (where applicable).
5. Submit a pull request using the PR template.
6. Wait for review: we aim to review PRs within one week.

## Code of Conduct

Be respectful. This is a community resource. Vendor spam, self-promotion without disclosure, and hostile behavior will not be tolerated.

If you represent a company whose tool you are adding, please disclose that in your PR description.

## Questions?

Open an issue or reach out to [TrazTech](https://traztech.ca) if you have questions about contributing.
